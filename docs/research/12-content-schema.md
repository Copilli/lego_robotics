## Transformation and ownership

`source archive ? copy-first extractor ? source IR ? normalizer ? Activity + Asset library`

The source IR records every source control, literal, action, wire and locator.
The normalizer assigns application step types, labels, navigation and content
roles. The Lesson Engine reads normalized types and never executes legacy URIs,
NI nodes or archive filenames as code. Preserve source locators at every
transformation. Keep unsupported nodes/actions as inert reference records and
explicit diagnostics; never silently drop them or invent executable meaning.

## Activity schema field contracts

| Field | Draft contract / acceptance |
| --- | --- |
| schemaVersion / profile | Explicit version. `reference-example` permits absent payloads; future `local-library` must validate content availability and migrations separately |
| id / kind / robotId | Stable normalized identifiers independent of physical install path; mission is one activity kind |
| title / locale | Locale-keyed normalized title, with source/author origin; source text bindings retained even if the normalized display title differs |
| source | Product, known app/content versions, robot, mission, relative originalPath, originalResourceId, SHA-256. Unknown fields stay UNKNOWN; install root is a local binding, not a public username |
| rights | Separate redistribution status from local possession/import. UNKNOWN does not authorize publication |
| entryStep / steps | Unique IDs and directed graph; references must resolve; declared terminals and branching conditions required before production normalization |
| step.type | VIDEO, BUILD, QUESTION, PROGRAMMING, HARDWARE_CONNECTION, PROGRAM_TRANSFER, EXECUTION, TEST, TEXT as sample roles; naming in example is authoritative for this draft, taxonomy remains open |
| step.label / labelOrigin | Application-authored short descriptions, distinct from original lesson prose |
| sourceSlideIndex / sourceLocator | Trace to flattened document-order index and archive member/control; these locators are not original IDs or real XPath expressions |
| assetIds / textBindings | Referenced asset identities plus source text locators, SHA-256, character count. Example has normalizedPayload null; private import must preserve full text and record conversion/sanitization |
| next / executionAllowed | Explicit normalized edges. Sequential order inferred from source flags is EXPERIMENTAL; sample executionAllowed false everywhere |
| buildSequence | Ordered `{ordinal, assetId}` records; preserve numeric order 0?47 rather than lexicographic filenames |
| legacyActions | Inert provenance only. Production semantics require explicit typed replacements and validation; no arbitrary script, URI or native call dispatch |
| hardware | Ports, motor/sensor types, confidence and evidence. Empty sensorOperations means no sensor operation found in this program, not no physical sensors |
| runtime | Execution capability separate from reference availability. Example workspace null, executionAllowed false and programConversion REFERENCE_ONLY |
| robotContext / missionMedia | Robot intro/cover separate from mission video/cover; context video is not automatically inserted into the mission flow |
| dependencies | Shared resource, guide/help and next-mission relationships, with unresolved/not-imported states |
| completion | Proposed learner confirmation, not original automatic assessment or verified pedagogical equivalence |
| unknowns | Explicit limitations displayed to maintainers/import reviewers; no compatibility invented to satisfy validation |

The concrete example's step vocabulary is generated from source-slide roles; it
is not a complete ontology. Branch choice needs accessible labels/conditions,
progress and resume policy in the next revision. Source slide order is evidence;
our graph traversal is a proposed normalized interpretation.

## Asset, provenance and deduplication

Every asset has hash-based id, sha256, size, sourceLocators, mediaType,
payloadPath and rights; detailed detected signatures/metadata remain in the linked inspection IR. Compare bytes/hash before deduplication. Preserve
all locations and consumers when identical bytes occur in multiple missions;
identity is not just a filename. The sample found 21 matching shared UI assets
across four sibling missions. Different candidates stay AMBIGUOUS.

For a future local library, payloadPath must be a safe relative managed-store
path; every required asset must exist and match its hash. Signature-based type
wins over a misleading extension. Preserve original bytes privately and create
separate derived assets for transcoding, captions or thumbnails, recording tool,
version, parameters, input hash and output hash. Media decode/playback is a
separate acceptance check from successful byte copying or header inspection.

Public reference manifests omit source prose, payloads and private absolute paths.
A private import may contain copyrighted payloads; neither this schema nor a
hash record establishes legal permission. Export must distinguish private backup
from public release and enforce reviewed rights per asset, including derivatives.

## Library / Lesson Engine / offline contracts (proposed)

- Library owns Activity versions, content-addressed assets, source bindings,
  import diagnostics and rights records. Import staging becomes visible only
  after validation; failures leave the previous library intact.
- Lesson Engine uses typed steps/edges and localized content; progress is a
  separate local record `{activityId, contentVersion, learnerScope, stepId}`.
  It handles branch selection, resume, unsupported content and unavailable hardware.
- ProgramReference stores source program/analysis; executable workspace and
  runtime plans are separate versioned artifacts with explicit conversion status.
- Offline acceptance covers a cold restart with network disabled, not merely an
  already cached lesson. Store assets durably; report quota, backups, eviction and
  migration failures. IndexedDB/OPFS/native filesystem/SQLite remain candidates.
- Accessibility requires readable focus order, touch targets, alternatives to
  drag-only interaction, build-image descriptions and captioned video. Source
  images/text do not automatically satisfy these requirements.

## Validation and unresolved generality

Run `python -B tools/validate_track3r_example.py` for the sample's asset/provenance,
22 reachable steps, two routes, terminal boundaries and 48 build-image mappings.
It does not validate arbitrary activities, media playback, instruction semantics,
source application behavior or legal rights. Add a formal schema and migrations
before treating the draft as an interchange standard. Validate one Lab and one
Classroom lesson before asserting cross-product coverage. See [17](17-preservation-milestone.md).
